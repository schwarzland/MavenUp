After installing the plugin, open the MavenUp tool window from the IDE's tool-window bar. It is available for Maven projects and gives you a clear overview of the dependencies, plugins, and parent entries used by your project.

First-time workflow

  1. Open the tool window: The table loads your project data from the active Maven modules and shows dependencies, plugins, and parent POM entries. You can also view entries from dependencyManagement and pluginManagement, and the parent section is listed as a dependency with type parent.
  2. Refresh if needed: Use Refresh to reload the current project state and clear any previously selected update values. This is useful after editing a pom.xml or after a Maven import.
  3. Check for newer versions: Click Search for New Versions to query Maven repositories and compare the current version of each item with the newest available version. A green checkmark ("✓") means the item already matches the latest known version; an upwards arrow ("↑") shows that a newer release is available.
  4. Choose the version to apply: In the New Version column, select the version you want to use. When multiple entries share the same Maven property such as ${spring.version}, MavenUp keeps the selection in sync automatically. The dropdown text is bold when a pending change is selected, and the tooltip explains the current status.
  5. Select versions in bulk: Open the Select Highest Version dropdown in the top action toolbar to apply a version to many dependencies at once — Select Highest Major Version picks the highest available version and Select Highest Minor Version stays within each dependency's current major line. Both act only on the currently visible rows, so any active filter narrows their scope. Use the separate Reset All to Current Versions toolbar action to discard all selections. When no filter is active it asks for confirmation first, and you can disable this from the dialog's "Don't ask again" option or in the settings; when a filter is active it instead asks whether to reset all dependencies or only the currently filtered ones.
  6. Update your project: Click Update to review the planned changes in a confirmation dialog and apply the selected versions to the relevant pom.xml files. The Sync Maven Changes after update checkbox is enabled by default and triggers the IDE's Maven sync immediately after the change.

Navigate and inspect entries

  • Filter the table: Type in the filter field above the table to narrow the list by GroupId, ArtifactId or Property, and use the combo boxes to filter by dependency type, pending version changes, available updates, or security findings. You can also right-click a GroupId, ArtifactId, or Property cell and choose Filter by "..." to filter by that exact value. The updates filter becomes available after a successful "Search for New Versions" and then shows only rows with a newer version; the vulnerabilities filter becomes available after a successful "Scan for Vulnerabilities". All filters combine so only matching rows remain visible. Use the reset button at the end of the filter row to clear all filters at once.
  • Sort the table: Click a column header to cycle through ascending, descending, and the original pom.xml order; sortable columns show a header indicator icon (a dimmed double arrow when unsorted, a directional arrow when sorted), while the Current Version, Vulnerabilities, and New Version columns stay unsorted.
  • Jump to the source: Double-click a row (or single-click if configured) to open the matching dependency or plugin entry directly in the editor.
  • Use the context menu: Right-click any row to access Filter by "..." (shown when you right-click a GroupId, ArtifactId, or Property cell to filter the table by that value), Navigate to pom.xml, Open in Maven Repository, Set Highest Major Version and Set Highest Minor Version for just that dependency (available once its versions have been retrieved via "Search for New Versions"), Reset to Current Version to discard that dependency's selection, and Show Vulnerability Details (disabled when the dependency has no findings). All entries stay visible and only toggle their enabled state.
  • Open the current artifact page: Select a row and use the top action toolbar to open the current version in the configured repository browser, such as MVN Repository or Sonatype Central.

Check for security issues

  1. Run a vulnerability scan: Click Scan for Vulnerabilities to check the direct dependencies and, when enabled, their resolved transitive dependencies. Results are shown in the Vulnerabilities (Current) column.
  2. Inspect the findings: Select a dependency with findings and click Vulnerability Details or click the populated vulnerability cell. The dialog opens a split view: the upper table lists the advisories (component, source, advisory ID, aliases, and severity) for the direct dependency and related transitive findings, while the lower detail pane shows the selected advisory's affected component with an Open on ... link to the configured repository browser, the CVSS vector and fixed-in versions when available, and the full summary and references as clickable links. The Severity column is color-coded by severity, matching the tool window's vulnerability column. Every table column is sortable by clicking its header (ascending, descending, or unsorted); the Severity column leads with the most critical findings and highest CVSS score on the first click.

Adjust the plugin to your workflow

Open Settings > Tools > MavenUp to personalize the plugin. The options are stored globally and apply to all your projects. They are organized into three groups — Appearance, Versions & Updates, and Vulnerability Check. You can choose the repository browser, enable single-click navigation, choose a three-state auto-selection strategy for updates (keep current version, highest version, or latest minor in the current major line), filter out unstable releases, choose whether to stop after a successful Maven Central lookup, and configure an optional Sonatype OSS Index API token. These options are meant to make first-time use fast and keep the tool window practical for everyday dependency maintenance.
