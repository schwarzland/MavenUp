# Tool Window & UI

Features of the MavenUp tool window: table content, navigation, context menus, toolbar, filtering, and sorting.

Back to the [feature overview](../../FEATURES.md).

- **Maven-only tool window availability**: The MavenUp tool window is shown for Maven projects and becomes available after Maven import if needed. It appears in the tool window bar with a dedicated MavenUp icon (with a Light and Dark theme variant) instead of a generic IntelliJ icon.
- **Status badge on the tool window icon**: After a refresh or a vulnerability scan the tool window icon carries a small badge dot rendered by the IntelliJ platform, so the current state is visible even while the tool window is collapsed: red for at least one high or critical finding, yellow for findings up to medium severity, and blue when no vulnerability is known but newer versions are available. Following the IntelliJ UI guidelines only one badge is shown at a time and no badge appears when there is nothing to act on. The badge is removed when the tool window is disposed and can be limited to vulnerabilities or switched off in the settings.
- **Dependency and plugin overview**: Displays dependencies, plugins, and the parent POM from `pom.xml` in a table.
- **Parent POM support**: The `<parent>` section of each `pom.xml` is listed as a dependency with type "parent", including version checks and updates; property-based parent versions are resolved to a concrete version.
- **Support for managed scopes**: Includes `dependencyManagement` and `pluginManagement` entries.
- **Input validation for displayed entries**: Skips dependencies and plugins without `groupId` so invalid entries are not shown.
- **Navigation to source in `pom.xml`**: Jumps directly to the matching dependency/plugin entry (single or double click, configurable). Clicking a non-empty cell in the **Property** column jumps to the property definition inside `<properties>` instead — including properties declared inside a `<profile>` — and falls back to the dependency entry when the property is not defined in any `pom.xml` of the project. A tooltip on each dependency row adapts its text to the configured click mode and to the clicked column ("Click to navigate to pom.xml | Right-click for more options" or "Click to navigate to the property definition in pom.xml | Right-click for more options").
- **Context menu on dependency rows**: Right-clicking any dependency row opens a context menu with **Filter by "..."** (only shown when right-clicking the GroupId, ArtifactId, or Property column with a non-empty value; sets the exact clicked value as the sole text filter, replacing any existing filter text, and applies it immediately), **Navigate to pom.xml** (jumps to the entry in the editor), **Navigate to Property Definition** (jumps to the `<properties>` entry that holds the version; disabled when the row has no version property), **Open on [Browser]** (opens the matching version page in the configured repository browser, with the configured browser name shown in the label — e.g. *Open on MVN Repository* or *Open on Sonatype Central*), **Set Highest Major Version** and **Set Highest Minor Version** (select, for the right-clicked dependency only, the highest available version across major lines or the highest version within its current major line; both are disabled until that dependency's available versions have been retrieved), **Set Recommended Version** (selects the recommended fix version for the right-clicked dependency's own security findings; disabled when the dependency has no findings of its own or no fetched version reaches the recommendation), **Reset to Current Version** (discards the selection for the right-clicked dependency only and is disabled unless a differing version is selected), and **Show Vulnerability Details** (opens the vulnerability findings dialog; disabled when the dependency has no findings). All entries stay permanently visible and only toggle their enabled state, so the menu layout is stable and discoverable.
- **Open in Repository action**: A selection-dependent action in the top action toolbar opens the current version of the selected dependency in the configured repository browser. Its tooltip dynamically reflects the configured repository browser name (e.g. **Open on MVN Repository** or **Open on Sonatype Central**), equivalent to the **Open on [Browser]** context menu entry.
- **Safe update workflow**: Shows a confirmation dialog before applying changes to `pom.xml`, with a **Sync Maven Changes after update** checkbox (enabled by default) to automatically trigger the IDE's Maven sync after the update. The checkbox is bound to the persistent **Sync Maven changes after update** setting, so both stay in sync and the last choice is remembered. Its overview table sorts the **Group Id**, **Artifact Id**, and **Type** columns through the same ascending → descending → unsorted cycle and header indicators as the other plugin tables, while the two version columns stay unsorted. Updates coming from a purely transitive dependency are marked in the **Type** column as `transitive -> managed dependency`.
- **Two-tier action toolbar**: The tool window presents its actions in a top IntelliJ `ActionToolbar` above the view tabs; core actions (Refresh and Search for New Versions, Scan for Vulnerabilities, Update) are separated by a separator from a **Select Highest Version** dropdown that groups the two highest-version actions (Select Highest Major Version, Select Highest Minor Version) plus a Select Recommended Version action and a standalone Reset All to Current Versions action, then the selection-dependent actions (Open in Repository, Vulnerability Details), with Settings placed at the end. The toolbar always acts on the table of the active tab. Actions render either as icon-only buttons (with tooltips) or as buttons with text labels (default), configurable in the settings; when text labels are enabled the buttons show shortened labels (e.g. "Refresh", "Scan", "Update", "Highest", "Reset", "Open", "Details") while their tooltips keep the full text so the toolbar stays compact on low screen resolutions. The tooltip is identical in both display modes, always showing the full text as a wrapping description.
- **Combined refresh and version search**: A single toolbar action reloads the dependencies from the `pom.xml` files, discards previous version selections and vulnerability results, and immediately searches online for new versions, so no separate step is needed to fill the **New Version** column. It is available in both tool window tabs and disabled only while a refresh or update check is already running.
- **Explanatory empty states of the dependency table**: While a refresh or a version search is running, the dependency table stays empty and its empty state names the running operation instead of showing intermediate rows — mirroring the transitive vulnerabilities view — and the rows are rebuilt once the operation has finished. Without a running operation the empty state distinguishes whether no dependencies were loaded at all or whether the active filter hides every row.
- **Automatic version search**: The same combined action runs automatically when the tool window loads its project data and after every finished Maven import or resync, so the **New Version** column is populated without manual interaction. It is controlled by the "Search for new versions automatically" setting (default: on) and only applies while the tool window is open, so no background network requests happen otherwise.
- **Fixed column order**: All plugin tables enforce single-row selection and prevent column reordering, so columns keep their defined order and cannot be dragged around.
- **Content-fitted column widths**: All plugin tables trim their column widths to the actual content (bounded by a minimum and maximum) after being populated and then scale the columns proportionally with the window or dialog size, so as much as possible stays readable without manual resizing.
- **Uniform row height**: All plugin tables use the row height recommended by the IntelliJ styleguide (24px, scaled to the IDE's UI scaling) instead of deriving it from font metrics and cell renderers, so rows are equally high across all tables and on every operating system.
- **Dependency table filtering**: A filter row above the main table combines a text field that filters by GroupId, ArtifactId or Property (case-insensitive substring match) with five combo boxes filtering by dependency type, version source (All / Inherited / Declared), available updates (All / Available / Up to date), pending version changes (All / Will update / Unchanged), and security findings (All / Any / Own / Transitive / None); the combo box options are kept short and are explained in full by each control's tooltip. Only rows matching all active filters remain visible. The text field can also be filled from the row context menu via **Filter by "..."** on a GroupId, ArtifactId, or Property cell. The version combo box is enabled only while at least one row has an inherited version and lets you hide either the inherited rows or the rows declaring their own `<version>` tag; the updates combo box is enabled only after a successful "Refresh and Search for New Versions" run and then shows only rows for which a newer version is available; the pending combo box is enabled only once at least one row has a version selection differing from its current version; the vulnerabilities combo box is enabled only after a successful "Scan for Vulnerabilities" run and separates rows whose own dependency is affected (**Own**) from rows affected through their transitive dependencies (**Transitive**), while **Any** matches either kind of finding and **None** matches rows without any finding. Each control carries a tooltip explaining its effect, and a reset button at the end of the row clears all filters at once and is disabled while no filter is active.
- **Column-header sorting**: Clicking a column header cycles the dependency table through ascending, descending, and the original pom.xml order; the Current Version and New Version columns stay unsorted. The Vulnerabilities column sorts primarily by the highest severity of its findings and secondarily by the number of findings, so ascending order lists the least critical dependencies first and descending order the most critical first. Sortable columns carry a header indicator icon — a dimmed up/down double arrow when unsorted and a single up/down arrow reflecting the active sort direction — so sortability is discoverable at a glance.
