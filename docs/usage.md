# Usage

The plugin opens a tool window named **MavenUp** (usually docked on the left or bottom edge of the IDE). It is identified in the tool bar by its own MavenUp icon (with a light and dark variant).

1. **Refresh**: Reloads the project data, populates the table, and resets the **New Version** column. While it runs, **Scan for Vulnerabilities** is disabled. (During **Search for New Versions** the newly loaded values are preserved.)
2. **Search for New Versions**: Searches online for available versions of all listed entries; **Scan for Vulnerabilities** stays disabled until it completes.
3. **New Version**: After the update check, a newer version can be selected in this column. A green check mark ("✓") signals that the selected version is the highest known one; an up arrow ("↑") indicates that a newer one exists. When a version other than the current one is selected, the text and symbol appear bold and colored. In the selection list, the currently used version is marked bold with "(current)" so it stands out — especially when the "show all versions" option is enabled. The tooltip provides details. Via the settings, the automatic pre-selection can be configured as a 3-state strategy (disabled, highest version, or highest minor version within the same major line).
4. **Select highest major/minor version and reset**: The **Select Highest Version** toolbar drop-down bundles two actions that set target versions with a single click: **Select Highest Major Version** selects the highest available version (even across major lines) and **Select Highest Minor Version** the highest version within each dependency's current major line — both affect only the currently visible (non-filtered) rows and show a tooltip hint when a filter is active. The standalone toolbar action **Reset All to Current Versions** discards all selections and restores the current versions. When no filter is active, a confirmation dialog (with a "Don't ask again" option) is shown first by default and can be disabled via the settings. When a filter is active, you are asked instead whether the reset should apply to all dependencies or only to the currently filtered (visible) rows.
5. **Update**: Applies the selected version changes to the corresponding `pom.xml` files. In the confirmation dialog, **Sync Maven Changes after update** can additionally be enabled (on by default) to apply the changes to the IDE's project model immediately. The selection is saved and synchronized with the setting.
6. **Scan for Vulnerabilities**: Checks direct components and, when enabled, transitive dependencies via OSV.dev and optionally OSS Index. The **Vulnerabilities (Current)** column, placed directly after **Current Version**, shows the total count, the transitive count, and the highest severity per direct dependency.
7. **Vulnerability Details**: Opens the findings of the selected dependency row in a master-detail split view. The upper table lists the findings with component, source, advisory ID, aliases, and severity; the columns are automatically trimmed to their content when the dialog opens for optimal readability; the **Severity** column is color-coded by severity — using the same color scheme as the vulnerability column in the main window. All table columns can be sorted by clicking the header (ascending, descending, unsorted), with the same sort indicators as in the main window; the **Severity** column shows the most critical findings first on the first click and sorts primarily by criticality and secondarily by CVSS score (highest first). The lower detail pane shows the selected finding's affected component with an **Open on ...** link to the configured repository browser, the CVSS vector, CWE identifiers, publish/last-modified dates, affected version ranges and the fixed-in versions when available, and the full summary, detailed description, and references as clickable links; clicking a link opens it in the browser. Overlong lines such as long reference URLs are soft-wrapped in the detail pane so no horizontal scrolling is needed. The action is only enabled when a dependency row with findings is selected. Clicking a populated vulnerability cell directly opens the findings of that dependency (also filtered to the selected row). A right-click on the selected row opens a context menu with **Open on [Browser]**.
8. **Transitive Vulnerabilities view**: A toggle button in the top action bar (among the selection-dependent vulnerability actions) switches the tool window from the main dependency table to a dedicated view that lists every transitive dependency with known vulnerabilities. It shows **GroupId**, **ArtifactId**, resolved **Version**, and a **Vulnerabilities** count column with the same severity coloring and sorting as the main table; rows are pre-sorted with the most critical findings first, and clicking a count opens the vulnerability details for that component. The toggle is only enabled after a scan found transitive vulnerabilities, and the filter row is hidden while the view is active. Pressing the button again returns to the main table with all its functions.
9. **Open on [browser]**: Opens the current version of the selected dependency in the configured repository browser. The action is located in the top action bar after the separator among the selection-dependent actions, is only enabled when a dependency row is selected, and shows the configured browser name as a tooltip (e.g. **Open on MVN Repository** or **Open on Sonatype Central**).
10. **Right-click context menu**: A right-click on a row offers **Filter by "..."** (only when right-clicking the **GroupId**, **ArtifactId**, or **Property** columns with a non-empty value; sets the clicked value as the sole text filter, replacing any existing filter text and applying it immediately), **Navigate to pom.xml**, **Open on [Browser]** (opens the current version in the configured repository browser), **Set Highest Major Version** and **Set Highest Minor Version** (select the highest available version across all major lines or the highest version within the current major line for the clicked dependency only; both are only available once that dependency's available versions have been retrieved), **Reset to Current Version** (discards the selection for the clicked dependency only and is enabled only when a differing version is selected), and **Show Vulnerability Details** (opens the dialog with the discovered security findings; disabled when the dependency has no findings). All entries remain permanently visible and only change their enabled state.
11. **Filter**: Above the table, the text field narrows the display case-insensitively by **GroupId**, **ArtifactId**, or **Property**; four combo boxes additionally filter by **Type** (dependency type), **Updates** (All / Update available / Up to date), **Pending** (All / Will update / Unchanged), and **Vulnerabilities** (All / Vulnerable / Not vulnerable). The option texts are worded to be self-explanatory so the selected value is understandable on its own. The **Updates** filter is only active after a successful version search (**Search for New Versions**) and then shows only rows with an available update; the **Pending** filter is only active once a version differing from the current one has been selected for at least one row; the **Vulnerabilities** filter is only active after a successful security check (**Scan for Vulnerabilities**). All filters work together so that only matching rows remain visible. **All** clears the respective filter. The text field can also be populated via the **Filter by "..."** context menu entry of a **GroupId**, **ArtifactId**, or **Property** cell. Each filter control shows a tooltip with a short explanation. At the end of the filter row, a reset button clears all filters at once; it is only enabled while at least one filter is set.
12. **Sorting**: Clicking a column header cycles the sort order: ascending, descending, and back to the original order from the `pom.xml`. Sortable columns carry an indicator icon in the header — a muted double arrow when unsorted and an up or down arrow when a sort direction is active — so sortability is recognizable at a glance. The **Current Version**, **Vulnerabilities (Current)**, and **New Version** columns are excluded from sorting.
13. **Adjust repository strategy**: In the settings under **Stop after a successful Maven Central lookup**, you can decide whether further private repositories are skipped after a successful Central lookup (faster) or queried additionally (more complete for private-only versions).
