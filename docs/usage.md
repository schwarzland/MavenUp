# Usage

The plugin opens a tool window named **MavenUp** (usually docked on the left or bottom edge of the IDE). It is identified in the tool bar by its own MavenUp icon (with a light and dark variant).

1. **Refresh and Search for New Versions**: A single action that reloads the project data, populates the table, discards previous version selections and vulnerability results, and then searches online for available versions of all listed entries. While the refresh or the version search is running, the table stays empty and its empty state explains the running operation; the rows are built once the search has finished. It also runs automatically when the tool window loads its project data and after every finished Maven import or resync, unless the corresponding setting is disabled. While it runs, **Scan for Vulnerabilities** is disabled. It is available in both tabs. Versions for vulnerable transitive dependencies are fetched automatically after a vulnerability scan instead.
2. **New Version**: After the update check, a newer version can be selected in this column. A green check mark ("✓") signals that the selected version is the highest known one; an up arrow ("↑") indicates that a newer one exists. When a version other than the current one is selected, the text and symbol appear bold and colored. In the selection list, the currently used version is marked bold with "(current)" and the recommended fix version of a dependency with its own security findings is marked bold with "(recommended)", so both stand out — especially when the "show all versions" option is enabled. The tooltip provides details. Via the settings, the automatic pre-selection can be configured as a 3-state strategy (disabled, highest version, or highest minor version within the same major line).
3. **Select highest major/minor version, recommended version, and reset**: The **Select Highest Version** toolbar drop-down bundles the actions that set target versions with a single click: **Select Highest Major Version** selects the highest available version (even across major lines), **Select Highest Minor Version** the highest version within each dependency's current major line, and **Select Recommended Version** the recommended fix version of every dependency that has security findings of its own — all affect only the currently visible (non-filtered) rows and show a tooltip hint when a filter is active. **Select Recommended Version** stays disabled until a vulnerability scan has found at least one such dependency whose recommended fix version is contained in the fetched versions. The standalone toolbar action **Reset All to Current Versions** discards all selections and restores the current versions. When no filter is active, a confirmation dialog (with a "Don't ask again" option) is shown first by default and can be disabled via the settings. When a filter is active, you are asked instead whether the reset should apply to all dependencies or only to the currently filtered (visible) rows. While the **Transitive CVEs** tab is active, this drop-down and the reset action operate on the transitive coordinates instead — again only on the rows visible under that view's filter, and the reset asks whether it should apply to all transitive coordinates or only to the filtered ones when a filter is active.
4. **Update**: Applies the selected version changes to the corresponding `pom.xml` files. In the confirmation dialog, **Sync Maven Changes after update** can additionally be enabled (on by default) to apply the changes to the IDE's project model immediately. The selection is saved and synchronized with the setting. The dialog's overview table can be sorted by clicking the **Group Id**, **Artifact Id**, or **Type** header (ascending, descending, unsorted) with the same sort indicators as the other tables; the two version columns are not sortable. Rows that stem from a purely transitive dependency show `transitive -> managed dependency` in the **Type** column, indicating that the dependency is pinned in `<dependencyManagement>` for the first time.
5. **Scan for Vulnerabilities**: Checks direct components and, when enabled, transitive dependencies via OSV.dev and optionally OSS Index. The **Vulnerabilities** column, placed directly before **Current Version**, shows the total count, the transitive count, and the highest severity per direct dependency.
6. **Vulnerability Details**: Opens the findings of the selected dependency row in a master-detail split view. The upper table lists the findings with component, origin, source, advisory ID, aliases, and severity. The **Origin** column sits directly after **Component** and states whether the finding comes from the dependency itself (`direct`), only from the dependency tree (`transitive`), or from a component that is pulled in transitively while also being declared in a `pom.xml` (`transitive, also declared directly`) — in the latter case the component has its own row in the main table and can be updated there. The columns are automatically trimmed to their content when the dialog opens for optimal readability; the **Severity** column is color-coded by severity — using the same color scheme as the vulnerability column in the main window. All table columns can be sorted by clicking the header (ascending, descending, unsorted), with the same sort indicators as in the main window; the **Severity** column shows the most critical findings first on the first click and sorts primarily by criticality and secondarily by CVSS score (highest first). The lower detail pane shows the selected finding's affected component with an **Open on ...** link to the configured repository browser, the CVSS vector, CWE identifiers, publish/last-modified dates, affected version ranges and the fixed-in versions when available, and the full summary, detailed description, and references as clickable links; clicking a link opens it in the browser. Overlong lines such as long reference URLs are soft-wrapped in the detail pane so no horizontal scrolling is needed. The action is only enabled when a dependency row with findings is selected. Clicking a populated vulnerability cell directly opens the findings of that dependency (also filtered to the selected row). A right-click on the selected row opens a context menu with **Open on [Browser]**.
7. **Transitive Vulnerabilities view**: The tool window header shows two tabs: **Dependencies** (the main dependency table with its own action bar and filter row) and **Transitive CVEs**. The **Transitive CVEs** tab lists every transitive dependency with known vulnerabilities. It shows **GroupId**, **ArtifactId**, a **Type** column, a **Vulnerabilities** count column, the resolved **Current Version**, and an editable **New Version** column — the same column order as the main table — with the same severity coloring and sorting as the main table. The **Type** column mirrors the main table's type (e.g. *managed dependency*) when the coordinate is declared in the pom.xml, or shows *transitive* otherwise, so components already pinned in `dependencyManagement` stay visible and recognizable. The **New Version** column is populated automatically after a vulnerability scan (available versions are fetched for the vulnerable transitive dependencies, so no separate version search is required) and lets you pick a target version that is pinned in `<dependencyManagement>` (creating the entry if needed) and applied through the shared **Update** action; each newly pinned entry gets an XML comment listing the fixed vulnerability IDs and noting the change was made by MavenUp. In the version dropdown the recommended fix version (lowest known version that resolves all vulnerabilities of the coordinate, taking the affected version ranges into account) is shown in bold with a *(recommended)* marker, next to the current version's *(current)* marker. Rows are pre-sorted with the most critical findings first; clicking a column header cycles sorting through ascending, descending, and unsorted (like the main table), while the **Current Version** and **New Version** columns are not sortable. Clicking a count opens the vulnerability details for that component. A right-click context menu (like the main table) offers **Filter by "..."** (only on the **GroupId** or **ArtifactId** column with a non-empty value), **Open on [Browser]**, **Set Highest Major Version**, **Set Highest Minor Version**, **Set Recommended Version**, **Reset to Current Version**, and **Show Vulnerability Details** for the clicked coordinate, and while the tab is active the toolbar's **Open on [Browser]** and **Vulnerability Details** actions also act on its selected row, while the **Select Highest Version** dropdown (including a **Select Recommended Version** action) and the **Reset All to Current Versions** action act on the transitive coordinates. The view has its own filter row above the table with the same look and behavior as the main table's: a text field filtering case-insensitively by **GroupId** or **ArtifactId**, an **Update** combo box (All / Available / Up to date), a **Pending** combo box (All / Will update / Unchanged), and a reset button that clears all filters at once; filtering by **Type** and **Vulnerabilities** is omitted because the view only lists vulnerable coordinates. Bulk version selection and the reset action apply only to the rows visible under this filter. The tab title shows the number of affected transitive coordinates and stays selectable at all times; if no scan has run yet or the filter hides every row, the table's empty state explains why nothing is listed. Switching back to the **Dependencies** tab returns to the main table with all its functions.
8. **Open on [browser]**: Opens the current version of the selected dependency in the configured repository browser. The action is located in the top action bar after the separator among the selection-dependent actions, is only enabled when a dependency row is selected, and shows the configured browser name as a tooltip (e.g. **Open on MVN Repository** or **Open on Sonatype Central**).
9. **Right-click context menu**: A right-click on a row offers **Filter by "..."** (only when right-clicking the **GroupId**, **ArtifactId**, or **Property** columns with a non-empty value; sets the clicked value as the sole text filter, replacing any existing filter text and applying it immediately), **Navigate to pom.xml**, **Open on [Browser]** (opens the current version in the configured repository browser), **Set Highest Major Version** and **Set Highest Minor Version** (select the highest available version across all major lines or the highest version within the current major line for the clicked dependency only; both are only available once that dependency's available versions have been retrieved), **Set Recommended Version** (selects the recommended fix version derived from the clicked dependency's own security findings; only available when the dependency itself is affected and a fetched version reaches the recommendation), **Reset to Current Version** (discards the selection for the clicked dependency only and is enabled only when a differing version is selected), and **Show Vulnerability Details** (opens the dialog with the discovered security findings; disabled when the dependency has no findings). All entries remain permanently visible and only change their enabled state.
10. **Filter**: Above the table, the text field narrows the display case-insensitively by **GroupId**, **ArtifactId**, or **Property**; five combo boxes additionally filter by **Type** (dependency type), **Version** (All / Inherited / Declared), **Update** (All / Available / Up to date), **Pending** (All / Will update / Unchanged), and **CVEs** (All / Any / Own / Transitive / None). The option texts are kept short to save space in the filter row; each control's tooltip explains the full meaning. The **Version** filter is only active while at least one row has an inherited version and lets you show only those rows (**Inherited**) or only the rows with their own `<version>` tag (**Declared**); the **Update** filter is only active after a successful version search (**Refresh and Search for New Versions**) and then shows only rows with an available update; the **Pending** filter is only active once a version differing from the current one has been selected for at least one row; the **CVEs** filter is only active after a successful security check (**Scan for Vulnerabilities**) and distinguishes findings in the dependency itself (**Own**) from findings in its transitive dependencies (**Transitive**), while **Any** matches both and **None** matches rows without findings. All filters work together so that only matching rows remain visible. **All** clears the respective filter. The text field can also be populated via the **Filter by "..."** context menu entry of a **GroupId**, **ArtifactId**, or **Property** cell. Each filter control shows a tooltip with a short explanation. At the end of the filter row, a reset button clears all filters at once; it is only enabled while at least one filter is set.
11. **Sorting**: Clicking a column header cycles the sort order: ascending, descending, and back to the original order from the `pom.xml`. Sortable columns carry an indicator icon in the header — a muted double arrow when unsorted and an up or down arrow when a sort direction is active — so sortability is recognizable at a glance. The **Current Version** and **New Version** columns are excluded from sorting, while the **Vulnerabilities** column is sortable by severity.
12. **Adjust repository strategy**: In the settings under **Stop after a successful Maven Central lookup**, you can decide whether further private repositories are skipped after a successful Central lookup (faster) or queried additionally (more complete for private-only versions).
13. **Inherited versions**: Entries whose version is not declared in the `pom.xml` — because it comes from the parent POM or an imported BOM — show their resolved version in the **Current Version** column in italics and a muted color, followed by an *(inherited)* marker; the tooltip explains where the version comes from, while all other rows keep the table's default text color. Such rows behave like any other row: you can select a version, use the bulk actions, the reset action, and every context menu entry. Applying the update writes an explicit `<version>` tag into the `pom.xml` and thereby pins the version.
14. **Navigation by click**: Clicking a row (single or double click, depending on the setting) opens the matching dependency, plugin, or parent entry in the `pom.xml`. Clicking a non-empty cell in the **Property** column jumps to the definition of that property inside `<properties>` — including `<properties>` blocks of a `<profile>` — and falls back to the dependency entry when the property is not defined in any `pom.xml` of the project. The cell tooltip states which target the click will open.
